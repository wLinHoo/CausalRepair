# CausalRepair: Bridging the Causality Gap in LLM-based APR via Dual-Slicing

CausalRepair is an Automated Program Repair (APR) framework designed to bridge the
"causality gap" in Large Language Model (LLM)-based repair. By leveraging a
synergistic dual-slicing strategy, the framework constructs a **Minimal Causal
Context** that eliminates noise from unexecuted code and resolves test context
ambiguity.

This repository contains the code used to run the experiments and the correct
patches generated by our study.

## Overview

- **Constructing Minimal Causal Context:** context-aware static slicing on the
  test side and execution-trace-based dynamic slicing (via Slicer4J) on the source
  side to isolate bug-related dependencies. The precomputed dynamic slices are
  bundled in `Defects4J/d4j_slice_info.json`, so Slicer4J is not required to run
  the repair.
- **Conversation-driven Iterative Repair:** a generate–validate–feedback loop where
  the LLM refines patches based on real-time execution diagnostics.
- **Patch Augmentation:** generates diverse variations of plausible patches to
  mitigate test-suite overfitting and increase the likelihood of semantic correctness.

## Repository structure

```
.
├── iterative_repair.py          # Stage 1: causal context + iterative repair
├── collect_plausible_patches.py # Stage 2: collect test-passing patches
├── augment_patches.py           # Stage 3: patch augmentation
├── utils/
│   ├── api_request.py           # LLM API request handling (keys from env vars)
│   ├── parse_d4j.py             # Defects4J data parsing
│   ├── prompt.py                # Prompt templates
│   └── validate_d4j.py          # Patch validation via Defects4J
├── Defects4J/                   # Dataset metadata: bug functions, test info,
│                                #   precomputed dynamic slices, fault locations
├── Results/correct_patches/     # Correct patches produced by our study
├── requirements.txt
├── Dockerfile                   # Reproducible runtime (recommended, see below)
└── scripts/                     # Docker entrypoint + run script
```

## Option A — Run with Docker (recommended)

Docker gives you a fully configured environment (JDK 8 + Defects4J 2.0.1 +
Python 3.12) with a single build. You only need to provide your own LLM API key
at run time.

```bash
# 1. Build
docker build -t causalrepair:latest .
#    (In regions where archive.ubuntu.com is slow/unreliable, pass an apt mirror:
#     docker build --build-arg APT_MIRROR=mirrors.ustc.edu.cn -t causalrepair:latest . )

# 2. Sanity-check Defects4J (optional)
docker run --rm causalrepair:latest d4j-check

# 3. Run the full pipeline (paper settings: iterative 5x3 -> collect -> augment 10)
docker run --rm \
    -e SILICONFLOW_API_KEY=sk-yourkey \
    -v "$PWD/results:/results" \
    causalrepair:latest run
```

Configure scope and budget via environment variables:

| Variable | Purpose | Default |
|----------|---------|---------|
| `SILICONFLOW_API_KEY` / `OPENAI_API_KEY` / `ZHIPU_API_KEY` | API key for the provider | — (required) |
| `CAUSALREPAIR_PROVIDER` | `siliconflow` / `openai` / `zhipu` | `siliconflow` |
| `CAUSALREPAIR_MODEL` | model name | `deepseek-ai/DeepSeek-V3` |
| `D4J_VERSION` | `1.2` / `2.0` / `all` | `all` |
| `MAX_ROUNDS` / `MAX_ATTEMPTS` / `AUG_ATTEMPTS` | repair budget | `5` / `3` / `10` |

Results are written to the mounted `results/` directory. The full run over the
entire benchmark is long-running (hours to days) and resumable — already-processed
bugs are skipped on restart.

## Option B — Run on a bare host

### 1. Prerequisites

- **JDK 1.8** (required by Defects4J 2.x):
  ```bash
  export JAVA_HOME=/usr/lib/jvm/java-1.8.0-openjdk-amd64
  export PATH=$JAVA_HOME/bin:$PATH
  ```
- **Defects4J 2.0.1** — install from https://github.com/rjust/defects4j and add
  its binaries to your PATH:
  ```bash
  export PATH=$PATH:"path2defects4j"/framework/bin
  ```
- **Python 3.12** (the version used in our experiments):
  ```bash
  pip install -r requirements.txt
  ```

### 2. Configuration

Set your API key and (optionally) point the code at your Defects4J installation
and data directory via environment variables:

```bash
export SILICONFLOW_API_KEY=sk-yourkey          # or OPENAI_API_KEY / ZHIPU_API_KEY
export DEFECTS4J_CMD=/path/to/defects4j/framework/bin/defects4j
export CAUSALREPAIR_DATA=$PWD/Defects4J         # dataset metadata directory
```

### 3. Pipeline

**Step 1 — Iterative Repair.** Constructs the causal context and engages in
multi-round debugging with the LLM.
```bash
python iterative_repair.py \
    --provider siliconflow \
    --model "deepseek-ai/DeepSeek-V3" \
    --folder ./results \
    --d4j_version all \
    --max_rounds 5 \
    --max_attempts_per_round 3 \
    --use_slice
```

**Step 2 — Collect Plausible Patches.** Extract patches that pass all tests.
```bash
python collect_plausible_patches.py \
    --input_file ./results/repair_result_iterative.json \
    --output_file ./results/plausible_patches.json
```

**Step 3 — Patch Augmentation.** Explore the solution space around each plausible
patch to find the correct fix.
```bash
python augment_patches.py \
    --input_plausible ./results/plausible_patches.json \
    --output_folder ./results/augmentation \
    --max_attempts 10
```
